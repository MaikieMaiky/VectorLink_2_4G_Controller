# 显示与提示系统讲解

## UI 任务职责

UiTask 每 10 ms 运行一次：

- 取得最高优先级蜂鸣器请求。
- 推进蜂鸣器片段状态机。
- 检查 OLED 重试、低电和失联告警。
- 每累计 100 ms 渲染一次 OLED。

蜂鸣器更新频率高于屏幕刷新频率，因此短音段不会受 100 ms 刷新周期限制。

## OLED 初始化与降级

初始化先使用 `HAL_I2C_IsDeviceReady()` 探测 `0x3C`。未检测到屏幕时返回失败，其他任务不受影响。

初始化成功后发送 SSD1306/SSD1315 常见命令序列，并清空屏幕。运行中若传输失败，`ready_` 变为 false，UiTask 每 5 秒重试。

这种“功能降级”比调用全局 `Error_Handler()` 更合理，因为遥控器核心功能是输入和无线，显示不是安全关键路径。

## 帧缓冲布局

128x64 单色屏需要：

```text
128 * 64 / 8 = 1024 bytes
```

SSD13xx 将屏幕分成 8 个 page，每个 page 有 128 字节，每字节表示同一列的 8 个垂直像素：

```text
index = page * 128 + x
page  = y / 8
bit   = y % 8
```

`DrawChar()` 遍历 5x7 字模并设置对应 bit。帧缓冲让页面绘制与 I2C 传输分离，避免每画一个像素都访问总线。

## 为什么缓冲区是静态对象成员

`g_oled` 具有静态存储期，它的 1 KiB 数组进入 ZI/BSS 区。若 `OledDisplay oled;` 是 UiTask 局部对象，缓冲会占用任务栈，容易造成隐蔽栈溢出。

这也是阅读 map 文件时要区分“静态 RAM”和“FreeRTOS 动态任务栈”的原因。

## I2C 更新

屏幕使用水平寻址，先设置列 0..127、page 0..7，再发送全部数据。

数据按 16 字节分块，每块前加 `0x40` 控制字节。分块的考虑：

- HAL 调用保持有界。
- 不需要额外 1025 字节 staging buffer。
- 失败时可尽快返回并触发重试。

代价是 I2C 事务数较多。400 kHz 下 10 Hz 全屏刷新对本项目足够。

## 两个页面

主页显示四轴、按键位图和电池。无线页显示初始化、连接、成功率、序号和遥测。

K9 的按下沿切换 `page`，不是根据电平持续切换，因此长按不会高速翻页。

## 蜂鸣器状态机

每种提示由若干 `Segment` 组成：

```text
frequency_hz + duration_ms
```

频率为 0 表示静音间隔。`Play()` 只选择模式并启动第一个片段，`Update()` 根据经过时间切换后续片段，因此不阻塞任务。

TIM4 计数频率为 1 MHz：

```text
ARR = 1,000,000 / frequency - 1
CCR = period / 2
```

得到约 50% 占空比。

## 模式优先级

`BuzzerPattern` 枚举值顺序同时表示优先级。故障音高于按键音。UiTask 处理的共享请求只保留当前最高优先级事件。

这是一种简化策略：它适合提示音，但不保证每个低优先级请求都被播放。如果需求变为“所有声音事件不能丢”，应改为队列。

## 常见误区

- OLED I2C 地址在 HAL 中需要左移一位传入。
- 字模字节方向必须匹配 page 布局，否则字符会旋转或错位。
- 1 KiB 缓冲对 F103C8 的 20 KiB RAM 并不小，应持续看 map。
- `HAL_TIM_PWM_Start()` 只启动波形，不会自动在指定时长后停止。
- 枚举顺序被用于优先级，新增模式时不能随意插入。
